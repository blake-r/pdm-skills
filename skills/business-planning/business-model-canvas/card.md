# Business Model Canvas

## Essence

Business Model Canvas is a template that describes a company's business model on one sheet in nine blocks: for whom the company creates value, what it offers, how it delivers and earns money, what it rests on, and what it costs.

| Block | Question |
|---|---|
| Customer segments | for whom we create value |
| Value propositions | what customer problem we solve and what we offer |
| Channels | how the customer finds out about, buys and receives the offer |
| Customer relationships | how we attract and retain customers |
| Revenue streams | what customers pay for and how |
| Key resources | what the model cannot work without |
| Key activities | what we do to make the model work |
| Key partners | who helps and what we get from them |
| Cost structure | the main cost items |

The right side of the canvas describes customer value and revenue; the left side describes what is needed to create that value, and the costs.

## When to use and when not to

Use it when a company launches a new line of business and needs to agree on how it will earn money; when you compare the current business model with a new one; when you look for which resources already exist and what new revenue they could bring.

Do not use it in place of a financial model: the canvas shows what the business is made of, but it does not calculate revenue, margin or payback. For a single feature inside a product the canvas is too large.

Limits:

- **The canvas is a set of assumptions.** Until the blocks are tested with customers, it is a hypothesis, not a description.
- **No time and no competitors.** The canvas is a snapshot of the model, without dynamics and without comparison with the market.
- **Links between blocks are not visible on their own.** They must be stated: which resource supports which proposition and which revenue follows from it.

## Scheme

```
┌────────────┬────────────┬──────────────┬────────────┬────────────┐
│ Key        │ Key        │ Value        │ Customer   │ Customer   │
│ partners   │ activities │ propositions │ relations  │ segments   │
│            ├────────────┤              ├────────────┤            │
│            │ Key        │              │ Channels   │            │
│            │ resources  │              │            │            │
├────────────┴────────────┴──────┬───────┴────────────┴────────────┤
│ Cost structure                 │ Revenue streams                 │
└────────────────────────────────┴─────────────────────────────────┘
```

## How to apply

1. **Start with customer segments:** for whom you create value. If there are several segments with different propositions, make a separate canvas for each or mark the blocks with a color per segment.
2. **Describe the value proposition** for each segment.
3. **Fill in channels, customer relationships and revenue streams** — the right side.
4. **Fill in key resources, key activities and key partners** — the left side, then the cost structure.
5. **Check the links:** each proposition is backed by resources and activities, each brings revenue, and costs are covered by revenues.
6. **Identify the main assumptions** and decide what to test first: demand, willingness to pay, cost of resources. If an assumption does not hold, change the block and rebuild the canvas.

## Example

Safaricom is the largest telecom operator in Kenya. Strategyzer, the company of Alexander Osterwalder, one of the authors of the canvas, published the canvas of M-Pesa and numbered the blocks in the order in which the model was built:

| № | Block | On the Strategyzer canvas |
|---|---|---|
| 1 | Customer segments | mobile phone users |
| 2 | Key resources | existing telecom network; subscriber base |
| 3 | Value proposition | money transfers via mobile phone |
| 4 | Revenue streams | transaction fees |
| — | Channels | agent network |

The other blocks are not filled in on this canvas.

Source data: some subscribers were already sending each other airtime by SMS as a substitute for money. Bank services were expensive and unsuited to small payments: in 2009, 39 million residents had 352 ATMs and 491 bank branches.

Decision: in 2007 Safaricom repurposed the existing telecom network and subscriber base for the new proposition — money transfers via phone. Cash is exchanged for electronic money and back through an agent network, which Strategyzer says was built through 2018.

Result: two years after launch there were 10 thousand new registration requests per day. In 2010, more than 90% of all mobile money transactions in Kenya went through M-Pesa. By 2018 the network had grown to 110 thousand agents — 40 times more than the number of ATMs in the country; M-Pesa brought in 62.9 billion Kenyan shillings, about $625 million, — 28% of Safaricom's revenue.

Case source: Strategyzer, ["M-Pesa Business Model"](https://www.strategyzer.com/library/m-pesa-business-model).

## Common mistakes

- **A single "everyone" segment.** Without a specific segment, the proposition and channels are described for nobody.
- **Blocks without links.** The canvas is filled with lists, but it is not visible which resource supports which proposition and where the revenue comes from.
- **Describing the desired as fact.** Untested assumptions are written down as given and are never checked.
- **The canvas made once.** The model has changed, but the canvas has stayed the same.
