# Brief for the author: one tool card

Run commands from the repo root; all paths below are relative to it. You build ONE tool card, complete. Do not touch other files (especially `product_notes.md`). The only shared file you may change is `build/build_templates.py`, and only by adding your own spec class (see below); if the assignment says to write the class to a scratch file instead, do that. Do not commit anything.

## What to read first (mandatory)
1. `build/quality_gate.md` - criteria K1-K8; write so that every criterion scores 2.
2. Reference cards: `skills/development-execution/kanban-board/` (card.md, SKILL.md, template.pptx) and `skills/development-validation/test-case/` (template.xlsx). Copy their format, density and style.
3. The primary source of your tool, as named in your assignment line. If the tool is described in PAF (Product Architecture Framework, productframework.ru, author Sergey Tikhomirov, CC BY-SA 4.0, pages carry no dates), read that page too; cards for gaps may have no PAF page.

## What to create (everything in `skills/<category>/<slug>/`)
- `card.md` - in English, word limits per section (Essence 200, When to use and when not to 300, Scheme 200, How to apply 400, Example 400, Common mistakes 200, Source 200 words; each "See also" bullet's text 15 words); `uv run -q python3 build/quality_gate.py skills/<category>/<slug>/card.md` checks the section limits and the other mechanical criteria. H1 is the original tool name. Exactly eight H2 sections, in this order: Essence, When to use and when not, Scheme, How to apply, Example, Common mistakes, Source, See also. "See also" lists the tools of the set that are linked to this one, one bullet each in the form `- <Phrase> <Tool name>: <how to use them together>`, where the phrase is `Enhanced by`, `Alternative to`, `Preceded by`, `Followed by`, `Improved by` or `Used to improve`; the tool name is the H1 heading of its card. Outside "See also", name another tool only when the tool cannot be used without it (a hard dependency). Spell out terms and abbreviations at first mention.
- "Example" - a real public case with a link (SaaS in e-commerce, fintech, EdTech or GameDev; PaaS and IaaS products are also considered; cases from other industries are not accepted), taken all the way to the decision made, in which the tool itself is visible in its own form. Find it by search (WebSearch/WebFetch, browser User-Agent). If no suitable public case exists, take the best real case, say honestly in "Example" what it lacks, and report it as "K5=1" if the form or the decision is not visible. Invent nothing: numbers, quotes, dates, names and links must all be verified by opening the page.
- "Source" - authors, year, context, working links to the primary source (not only to PAF). Cite PAF as "description in PAF (Sergey Tikhomirov, productframework.ru, CC BY-SA 4.0, undated)" if it exists. If PAF gives only a name without a definition, build the card from the primary source of the method and say so honestly in "Source".
- `SKILL.md` - in English; triggers in the description; frontmatter `name` = slug, and `description`; two modes, "Mode: do" and "Mode: review"; the review checklist maps one-to-one to the items of "Common mistakes"; a link to card.md instead of retelling the theory; in do mode, first show the fill-in in chat and write the file only after confirmation; a JSON example (from the data of the "Example" case; empty values are null/omitted, invent nothing) and field length limits; the fill command runs from the repo root: `uv run scripts/fill_pptx.py <skill dir>/template.pptx data.json <out>.pptx` or `uv run scripts/fill_xlsx.py ...` (read `scripts/*.py` and the reference cards; JSON format: pptx - {"text":{...}}, xlsx - {"text","cells","rows"}; use null, not "").
- Exactly one template: `<slug>.pptx` OR `<slug>.xlsx`, by the form of the tool (visual - pptx, tabular - xlsx). Add a subclass of `PptxSpec` (visual) or `XlsxSpec` (tabular) to `build/build_templates.py` with a `rel` property returning `"<category>/<slug>/<slug>.pptx|xlsx"` and a `draw` method (`draw(self, prs, slide)` or `draw(self, wb)`), then rebuild with `uv run build/build_templates.py <slug>`. Use the helpers new_deck, header, box, text, label (pptx) or the openpyxl pattern of the sprint and test-case templates (xlsx). The output root `ROOT` defaults to `skills/` and can be overridden with the env var `BUILD_OUT`. Placeholders have the format `{{key: hint}}`. Check: `uv run scripts/fill_pptx.py <template> --list`, fill with the test JSON from SKILL.md, then `officecli validate`, `officecli view <file> issues`, `officecli close <file>`. For pptx render it: `bash build/render_pptx.sh <ABS-path-to-pptx> <slug>` (output goes to `$RENDER_OUT/<slug>`, default `/tmp/pdm-render/<slug>`; if Keynote says "Application isn't running", run `open -a Keynote`, wait, retry) and look at the PNG - text must not overflow the blocks. xlsx cannot be rendered (no soffice) - check formulas and validation logically; avoid N() on arrays, use SUMPRODUCT.
- All temporary files go to a scratch directory outside the repo (for example `/tmp/<slug>-work`); leave nothing extra in the repo.

## Shell
fish with GNU sed: `sed -i ''` does not work; edit files with the Edit/Write tools or Python.

## Final answer (short)
Category/slug; word count; the case (name, link); K5 (2, or 1 and why); what the sources did not contain; which items I should re-check; template verification (what you ran). Do not retell the card.

## Adding a card for a gap

A card for a missing method is created only when a primary source exists: the method's author or publisher, or the official page of a standard. A second independent source is welcome. A corporate source is used only for facts about that company; news and blogs are leads. Without a primary source, do not create the card: the maintainer records the decision in the Gaps section of `product_notes.md`.

The card builder does not edit `product_notes.md`. The maintainer, after the card passes `build/quality_gate.py`, adds the catalog entry, one row in the Selection table (`draft`), and the tool's position in every chain it belongs to.
