# Build tools

Scripts that generate the PPTX and XLSX templates of the plugin. They are developer tooling and are not shipped with the plugin skills.

## Source of truth

- Templates in `skills/<category>/<tool>/<tool>.pptx|xlsx` are the output of the builders in `build_templates.py`.
- Each template is a spec class in `build_templates.py`: a `PptxSpec` or `XlsxSpec` subclass with a `rel` property and a `draw` method. `Builder(spec).build(out)` makes the document, calls `draw`, and saves; the shared steps live only in `Builder`. Shared helpers are module-level functions in the same file. To change a template, edit its class, then rebuild. Do not hand-edit a template and leave the builder unchanged: the next rebuild would overwrite the change.
- Cards (`card.md`) are not generated by these scripts. They are written per the brief in `build/card_brief.md`, and `build/quality_gate.py` checks them mechanically; the quality gate is `build/quality_gate.md`, and the report goes to a temporary directory outside the repo (`QUALITY_REPORT` overrides the path).

## Running a builder

Run from the repository root:

    uv run build/build_templates.py [<name> ...]

With names, only the templates whose path contains one of them are built.
It writes `skills/<category>/<tool>/<tool>.*`. To build into a scratch directory first and compare, set `BUILD_OUT`:

    BUILD_OUT=<scratch dir> uv run build/build_templates.py <name>

## Files

- `build_templates.py`: the spec base classes `ToolSpec`, `PptxSpec`, `XlsxSpec`, `Builder`, shared helpers (slides, boxes, tables, charts, workbook styles), one subclass per template, and the output root (`BUILD_OUT` or `skills/`). Pptx parts (charts, embedded workbooks, images) are renamed `<tool>_<name>` on save, so decks merge without name clashes.
- `quality_gate.py`: mechanical checks of every card against the quality gate (structure, word limit per section, SKILL.md and template names, "See also" links). Prints only problems.
- `scan.py`: word count of one card. `section_stats.py`: word counts per section across all cards, with recommended limits. `record.py`: writes the quality report.
- `render_pptx.sh`: renders a PPTX to PNG for visual review on macOS with Keynote.
- `classification.md`: which category each tool belongs to.
- `card_brief.md`, `card_brief_review.md`: briefs for writing and reviewing one card.

The catalog of all tools is `product_notes.md` at the repository root.
